# 管理画面（職員向け）

日本語で質問と回答を入れると、他の言語は自動で翻訳され、
**質問回答集（`tools/faq_master.xlsx`）の「FAQ」「多言語」シートに追加される**。

ターミナルの操作は不要。ブラウザだけで完結する。
Excelを直接開いて編集しても構わない。どちらで編集しても同じファイルを見ている。

## 構成

| ファイル | 役割 |
|----------|------|
| `app.py` | 管理画面 |
| `faq_excel.py` | 質問回答集（Excel）の読み書きと、保存先の切り替え |
| `faq_translate.py` | 自動翻訳と、質問例の点検 |
| `faq_store.py` | 書き出した `faq.json` の保存先（手元のファイル / GitHub） |
| `log_stats.py` | 案内端末の記録の集計 |
| `components/layout_editor/` | 画面レイアウトを絵で動かす部品（HTML1枚。npmは使わない） |

### 画面レイアウトで動かせるもの

| つまむところ | 変わるもの | どこに保存されるか |
|---|---|---|
| ブロックの下の縁 | そのブロックの高さ | 「画面レイアウト」（設置場所ごと） |
| ブロック本体を上下へ | 並び順 | 〃 |
| 右上の × | 出す／出さない | 〃 |
| 立ち絵 | 立ち位置 | 〃 |
| 立ち絵の左上の四角 | 大きさ | 〃 |
| 吹き出しの左の縁 | 吹き出しの幅 | 〃 |
| **○の印** | **△の向く先（口の位置）** | **「キャラクター」（絵ごと・全端末共通）** |
| **縦の点線** | **吹き出しが顔にどこまで近づけるか** | **「キャラクター」（絵ごと・全端末共通）** |

○と点線だけは**絵そのものの形**なので、設置場所では分かれない。
同じ絵なら、据え置きでも観光客の端末でも口の位置は同じだから。
| `../.streamlit/config.toml` | 見た目の色（案内アプリと同じ緑に揃えてある） |

変換（Excel → faq.json）は `tools/build_faq.py` をそのまま使っている。
管理画面から書き出しても、コマンドで変換しても結果は同じ。

## 画面の構成

左の一覧から選ぶ。**毎日使うものを上、最初に決めたら滅多に触らないものを下**に
まとめてある。

| 分類 | 画面 | できること |
|------|------|-----------|
| | **ホーム** | いまの件数と、**反映されていない変更**が無いかを見る |
| 質問と回答 | 質問を追加・修正する | 日本語で1件入れて、翻訳を確認してから保存する |
| | 登録されている質問 | 設置場所・分類でしぼって一覧する。翻訳が足りないものも探せる |
| | まとめて翻訳する | 日本語だけの項目を探し、選んだ言語へまとめて翻訳する |
| 案内の設定 | **画面・キャラクター・声** | 中を切り替えて使う（URL は `screen?tab=…`）。どれも変えた結果をその場で見る・聞ける |
| | 　└ 画面レイアウト | 設置形態ごとに、ブロックをつかんで並びと大きさを決める。「大きく表示」で全画面になる |
| | 　└ キャラクター | 立ち絵を並べて見ながら、最初に立つものを選ぶ |
| | 　└ 読み上げの声 | 用意した音声を鳴らして確かめる／言語ごとの声・速さ・高さを、保存前に聞いて決める |
| | 　└ 読み方 | 1行ずつ「直す前／直したあと」を聞き比べる。文でも試せる（「荻町」→「オギマチ」） |
| | **現地の情報** | 中を切り替えて使う（URL は `local?tab=…`） |
| | 　└ 参考資料 | AIが答えを組み立てるときの下地 |
| | 　└ 設置場所 | 案内所の座標と、各言語での表記 |
| | 　└ 言い換え | 観光客の言い方を、質問例の語へ橋渡しする |
| 運用 | 案内アプリへ反映する | Excelから `faq.json` を書き出す |
| | 利用状況 | 設置場所ごとに、何が聞かれたかを見る |

**どの画面も、直したあとに「案内アプリへ反映する」で書き出すまで案内端末には届かない。**
書き出し忘れが起きやすいので、ホームで「反映されていない変更」を出すようにしてある。

## 画面の写真を撮る

見た目を直したときは、全画面を撮って確かめられる。

```
streamlit run admin/app.py --server.port 8502 --server.headless true
python tools/shoot_admin.py
```

`tools/_shots/admin/` に入る（gitには含めない）。

## 手元で試す

初回だけ、専用の環境を用意する。

```
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r admin/requirements.txt
```

2回目以降はこれだけ。

```
.\.venv\Scripts\Activate.ps1
streamlit run admin/app.py
```

設定をしていない状態では、`tools/faq_master.xlsx` と `assets/faq.json` を
直接読み書きし、自動翻訳は使えない（日本語のみで保存できる）。

**Excelでそのファイルを開いたままだと保存できない。** 保存前に閉じること
（開いたままの場合は、その旨が画面に出る）。

## 公開する（Streamlit Community Cloud）

1. share.streamlit.io でアプリを作成し、Main file path に `admin/app.py` を指定
2. Settings → Secrets に次を貼る

```toml
[app]
password = "職員に伝える合言葉"

[github]
token      = "GitHubのアクセストークン"
repo       = "ユーザ名/リポジトリ名"
excel_path = "tools/faq_master.xlsx"   # 質問回答集（正データ）
path       = "assets/faq.json"         # 案内アプリが読むファイル
branch     = "main"

[anthropic]
api_key = "翻訳用のAPIキー"

[logs]
url   = "https://例.com/api/logs.php"   # 中継サーバの読み出し口
token = "中継サーバの config.php の log_token と同じ文字列"
```

- `[app]` を書かないと誰でも編集できてしまう。公開するなら必ず設定する
- `[github]` を書かないと保存が端末内で消えるので、公開時は必須
- `[anthropic]` を書かない場合、自動翻訳は使えないが日本語のみで運用できる
- `[logs]` を書かない場合、「利用状況」は使えないが、ほかは普通に使える

GitHubのトークンは、対象リポジトリの **Contents: Read and write** 権限だけ与えた
Fine-grained personal access token を使う。

保存すると、Excelとfaq.jsonがリポジトリに直接コミットされる。
誰がいつ何を変えたかはGitHubの履歴に残るので、間違えても戻せる。

職員は、公開されたURLを開いて合言葉を入れるだけでよい。
APIキーはこの設定の中にあり、職員が触ることはない。
翻訳はクラウド側で動くので、職員のパソコンには何も入れなくてよい。

## 翻訳に使うものを選ぶ

2通りから選べる。どちらもクラウド側で動く。

### Claude（既定・おすすめ）

```toml
[anthropic]
api_key = "..."
```

品質が最も安定している。料金は使った分だけ（未翻訳を全部埋めても数百円程度、
以後の追加は1件あたり数円）。**翻訳は年に数百円の世界なので、ここは品質で選んでよい。**

固有名詞の間違いが一番こわい。観光客は地名を手がかりに地図や看板と
突き合わせるので、「白山」を Shiroyama と訳されると別の山を探しに行ってしまう。
安いモデルほど、この種の間違いが出やすい。

### オープンなモデル（gpt-oss、Qwen など）

Groq・OpenRouter・Together など、オープンなモデルを動かしてくれるサービスを使う。
無料枠のあるサービスが多い。モデル自体はオープンなもので、
動かすのは相手のサーバなので、こちらで用意する機械は要らない。

```toml
[open_model]
base_url = "https://api.groq.com/openai/v1"   # OpenRouter なら https://openrouter.ai/api/v1
api_key  = "そのサービスのAPIキー"
model    = "openai/gpt-oss-120b"              # 安く済ませるなら openai/gpt-oss-20b

[translate]
engine = "open_model"    # 両方設定したときに、こちらを使う（既定はClaude）
```

OpenAI互換の窓口を持つサービスであれば、`base_url` と `model` を変えるだけで使える。
案内アプリのAI回答（`server/api/config.php`）と同じサービスを使い回せる。

料金はClaudeよりかなり安い（1件を5言語で Claude Opus 4.5円に対し 0.08円程度）。
**ただし固有名詞の間違いが出る。** 実際に試したときは次のような誤りがあった。

| 元 | 誤り | 正しくは |
|----|------|----------|
| 白川郷（韓国語） | 백가와고・백화고 | 시라카와고 |
| 白山 | Shiroyama | Hakusan（別の山になる） |
| 道の駅（韓国語） | 도로역 | 미치노에키 |
| であいの館（韓国語） | であいの館のまま | 데아이노야카타 |

文章のぎこちなさは伝わるので構わないが、**地名が違うと案内として成り立たない**。
使う場合は、**訳したあとに固有名詞だけでも必ず目視で確認する**こと。
どちらを使っているかは画面の左側に表示される。

> **提供されるモデルは入れ替わる。** Groqでは2026年8月に Llama 3.3 70B が
> 法人契約専用へ移った。翻訳が急に失敗するようになったら、
> まず `model` が今も提供されているかを確認する。

#### 無料枠を使う場合

無料枠は1分あたりの上限が低い（Groqは8,000トークン）。
まとめて翻訳すると必ず上限に当たるが、次のように自動で対処する。

- 上限に当たったら**待って続ける**（最大4回、職員は待つだけでよい）
- 返答が長すぎて切れたら、**件数を半分に分けてやり直す**
- 考えてから答えるモデルには、**考える量を控えめに指定する**
  （翻訳は深く考えても質が上がらず、枠と料金だけがかかる）

実測で、15件×5言語がおよそ80秒。70件すべてなら6〜7分かかる。
待てない場合は有料に切り替えると上限が上がる。

## その他の設定

「その他の設定」タブで、**Excelを開かずに**次の4つを直せる。
表の形はExcelのままなので、Excelで直しても管理画面で直しても同じ結果になる。

| 種類 | 何を決めるか |
|------|--------------|
| 言い換え | 観光客の言い方を、質問例の語へ橋渡しする（銀行→atm） |
| 設置場所 | 案内所の座標・範囲と、各言語での呼び名 |
| 参考資料 | AIが答えを組み立てるときの下地 |
| キャラクター | 画面に立つ絵・大きさ・高さ位置 |

キャラクターの数値（大きさ・高さ位置・口の高さ・顔の広さ）は、
**案内アプリ側で画面を見ながら決められる**。

```
https://＜ドメイン＞/webapp/?tune=1
```

つまみを動かして決まった数値を、ここへ書き写す。

行の追加は表の一番下、削除は行を選んで Delete キー。
直したあとは「案内アプリへ反映する」で書き出す。

> シートの下にある「※ …」の説明書きは、保存しても消えない。

## 読み上げの声を決める

「読み上げの声」タブで、**どの案内端末でも同じになるように**設定する。

### 用意した音声（VOICEVOXなどで作ったもの）

どの音声セットを鳴らすかを選ぶ。選んだ音声が無い回答は、端末の声で読み上げる。

### 端末の声（言語ごと）

| 決められること | 内容 |
|----------------|------|
| 優先する声 | 上から順に探し、その端末に入っている最初の声を使う |
| 速さ | 1.0が標準。小さいほどゆっくり |
| 高さ | 1.0が標準。大きいほど高い声 |

名前の一部が合えば採用する（`Microsoft Aria` と書けば
`Microsoft Aria - English (United States)` に当たる）。
書いた声がどれも入っていない端末では、その言語の声から自動で選ぶ。

> **端末に入っている声の一覧は、ここでは出せない。**
> Windowsには日本語とドイツ語、iPadには日本語とフランス語、というように
> 端末ごとに違い、管理者画面からはどの端末に何が入っているか分からない。
> 入っている声の確認と試し聞きは、案内端末の画面で行う
> （URLに `?setup=1` を付けて開く）。そこで選べば、その端末だけが変わる。

決めたあとは「案内アプリへ反映する」で書き出す。

## 利用状況を見る

「利用状況」タブで、案内端末で何が聞かれたかを見る。
**案内端末の画面からは見られない**ようにしてあるので、見るのはここだけ。

設置場所ごとに分けて出る。

| 見るもの | 何が分かるか |
|----------|--------------|
| その場で答えられた割合 | 職員に回さずに済んだ割合。設置の効果はこの数字で見る |
| 答えられなかった質問 | **質問回答集に足す候補**。ここを埋めると上の割合が上がる |
| その場所でだけ聞かれた質問 | その案内所向けの回答（設置場所を指定した回答）を足す候補 |
| よく聞かれた質問 | 音声ファイルを優先して用意すると効果的 |

「その場所でだけ聞かれた質問」は、ほかの案内所では出ていない質問を拾う。
「ここからバスに乗れますか」のように、**その場所ならではの困りごと**が出てくる。

記録が読めない場合は、中継サーバの `config.php` の `log_token` と
Secrets の `[logs] token` が同じ文字列かを確認する。

## 使い方（職員向け）

### 1件ずつ追加する

1. 「質問を追加・修正する」で、設置場所・分類・日本語の聞き方と回答を入れる
2. 「確認する」を押すと、翻訳結果が下に出る
3. 内容を確認し、必要なら直接直す
4. 「保存する」を押す（Excelに追加される）
5. 「案内アプリへ反映する」で「書き出す」を押す

### まとめて翻訳する

日本語だけ入っている項目がたくさんあるときは「まとめて翻訳する」を使う。

1. 翻訳する言語を選ぶ
2. 一度に翻訳する件数を決める（まず少数で試す）
3. 「この内容で翻訳する」を押す

すでに翻訳が入っている項目には触らない。
自動翻訳した行は、多言語シートの備考に「自動翻訳（要確認）」と入る。

### 聞き方の書き方

1行に1つの言い方を書く。**行の中の空白は「かつ」の意味**になる。

- `たばこ 吸える` → たばこ と 吸える の両方が入っているときだけ反応する
- `どこ` だけ → 関係ない質問にも反応してしまうので避ける（画面が注意する）

### 掲載の期間

お祭りなど期間限定の案内は「期間を決める」にチェックを入れて日付を指定する。
期間外の項目は書き出しのときに外れるので、消し忘れが起きない。
期間に入ったら、もう一度書き出せば案内に出る。

## 注意

- **保存は「あとから保存した人の内容」が残る。** 同じ項目をExcelと管理画面で
  同時に直すと、片方が消える。編集する前に「最新の内容を読み直す」を押すこと
- 自動翻訳した内容には「※自動翻訳」と表示される。
  料金や条件を含む回答は、公開前に必ず人が確認する
- 翻訳には料金がかかる（オープンなモデルの無料枠を使う場合を除く）。
  Claudeの種類は `faq_translate.py` の `MODEL` で決まる
  （既定は `claude-opus-5`。安く済ませるなら `claude-sonnet-5` に変える）
- 翻訳エンジンを変えても、質問例の作り方（行内の空白は「かつ」）は同じ指示を使う
- Excelに列を足しても壊れない。管理画面は知っている列だけを読み書きする
- 「設置場所」シート（案内所の座標と範囲）と、「よくある質問」列（画面に流す文言）は、
  いまのところExcelで直接編集する
- 備考に「※要確認（共通版の下書き）」と入っている項目は、自動で作った下書き。
  内容を確認し、印を消すこと
- 「言い換え」シート（観光客の別の言い方を吸収する表）は、いまのところExcelで直接編集する。
  書き方は本体のREADMEを参照
