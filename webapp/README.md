# Webアプリ版（本体）

Androidアプリ（Flutter）と同じ画面・同じ判定を、ブラウザだけで動かす。
インストールが要らず、タブレット・PC・スマートフォンのどれでも同じURLで使える。

## ファイル構成

| ファイル | 役割 | 元のFlutter |
|----------|------|-------------|
| `index.html` | 画面の骨組み | `lib/main.dart` |
| `styles.css` | 見た目（配置・色） | 各Widgetの装飾 |
| `js/app.js` | 画面と一連の流れの組み立て | `lib/main.dart` |
| `js/config.js` | 素材の置き場所・配信URL・待ち時間の設定 | `faq_repository.dart` の定数 |
| `js/faq-service.js` | FAQ検索と言い換えの吸収（← 将来ここだけ差し替える） | `lib/faq_service.dart` |
| `js/faq-repository.js` | FAQデータの取得（オンライン更新・キャッシュ・同梱の3段構え） | `lib/faq_repository.dart` |
| `js/speech-service.js` | 音声認識（Web Speech API） | `speech_to_text` パッケージ |
| `js/voice-service.js` | 読み上げ（音声ファイル → 無ければブラウザ音声） | `lib/voice_service.dart` |
| `js/answer-view.js` | 回答表示（字幕・写真・QRコード） | `lib/answer_view.dart` |
| `js/character.js` | キャラクター表情の表示 | `lib/character_view.dart` |
| `js/background.js` | 背景の集落を描く | `lib/background_view.dart` |
| `js/app-language.js` | 対応言語の定義と画面文言（← 言語追加はここから） | `lib/app_language.dart` |
| `js/question-log.js` | 質問の記録 | `lib/question_log.dart` |
| `js/log-screen.js` | 職員向けの記録確認画面 | `lib/log_screen.dart` |
| `js/ai-service.js` | AI回答の問い合わせ（設定したときだけ動く） | （新規） |

素材（`assets/faq.json`・音声・写真・キャラクター画像）はFlutter版とそのまま共有している。
質問回答集を更新すれば、実機・デモ・Webの3つすべてに反映される。

## 画面の構成

上から順に並べている。

| 位置 | もの | ねらい |
|------|------|--------|
| 上 | 会話の領域（キャラクターと吹き出し） | 回答を見せる |
| 2番目 | よくある質問（右から左へ流れる） | 押すだけで聞ける。声を出せない場所でも使える |
| 3番目 | 文字の入力欄 | 声が使えないとき、動作確認をするとき |
| 4番目 | 「話す」ボタン | 通常の使い方 |
| 下 | 言語の切り替え（一覧から選ぶ） | 場所を取らないよう一覧式にしている |

よくある質問は、**その端末でよく聞かれた順**に並ぶ（記録がまだ無ければ登録順）。
札の文字はその言語の質問例をそのまま使うので、押せば必ずその回答に当たる。
指を触れている間は流れが止まる。

文字入力・よくある質問・音声のどれで聞いても、検索も記録もまったく同じ扱いになる。

## 手元で動かす

リポジトリ直下で簡易サーバを立て、`/webapp/` を開く。

```
python tools/serve.py
```

→ ブラウザで http://localhost:8000/webapp/

AIの回答まで試すときは、PHPの簡易サーバを使う（中継が動くのはこちら）。

```
php -S 127.0.0.1:8000 -t .
```

> **`python -m http.server` は使わないこと。**
> ブラウザがファイルを取りに来ず、直したはずのものが反映されない。
> 新しいファイルと古いファイルが混ざり、
> 「◯◯ is not a function」のような止まり方をする。
> `tools/serve.py` は毎回確かめさせるので、この問題が起きない。

`index.html` をファイルとして直接開く（file://）と、
ブラウザの制限でJavaScriptの読み込みとマイクが動かない。必ずサーバ経由で開く。

## 公開する

`assets/` と `webapp/` を同じ場所に置いて配信すれば動く（サーバ側の処理は不要）。

- GitHub Pages: リポジトリをそのまま公開し、`https://ユーザ名.github.io/リポジトリ名/webapp/` を開く
- 社内サーバ・レンタルサーバ: 2つのフォルダをアップロードするだけ

**マイクは https か localhost でしか使えない**（ブラウザの決まり）。
公開するときは必ず https にする。

`assets/` を `webapp/` の中に移したい場合は、`js/config.js` の `ASSET_BASE` を
`'./assets/'` に変える。

## 画面の寸法を確かめる

目分量で直すと、別の画面幅で崩れる。
実際のブラウザに描かせて、幅と高さを数字で確かめる道具がある。

```
python tools/serve.py              # 別の窓で動かしておく
python tools/measure_layout.py     # 各部の大きさを測る
python tools/measure_characters.py # キャラクターごとの見え方を測る
```

スマートフォン・タブレット・ノートPC・設置端末の4つの大きさで、
はみ出していないか、文字が小さすぎないかが分かる。

```
【スマートフォン 指定393×852 / 実際の表示幅 393px】  横のはみ出し=なし
  上のバー           393×56   px (幅の100%) 文字16px    x=0
  キャラクター         170×315  px (幅の 43%) 文字16px    x=244
```

`--shot` を付けると `tools/_shots/` に画面写真も残る。

> ヘッドレスのブラウザは窓を500pxより狭くできないため、
> スマートフォンの幅は `tools/_measure_frame.html` の枠の中で測っている。

## 直したのに画面が変わらないとき

ブラウザが古いファイルを使っている。**Ctrl + Shift + R**（強制再読み込み）で直る。

起きやすいのは、`python -m http.server` で開いていたとき。
`tools/serve.py` か `php -S` を使えば起きない。

公開するときは `webapp/.htaccess` と `assets/.htaccess` が同じことをする
（毎回「変わっていないか」を確かめてから使わせる）。
**この2つのファイルも一緒にアップロードすること。**
設置端末は何日も開きっぱなしになるので、ここを抜かすと更新が届かない。

## 対応ブラウザ

| | 音声入力 | 読み上げ |
|---|---|---|
| Chrome / Edge（PC・Android） | ○ | ○ |
| Safari（iOS・Mac） | ○ | ○ |
| Firefox | ×（入力欄に切り替わる） | ○ |

iOS Safari は、画面に触れてから時間が空くと読み上げが鳴らないことがある
（ブラウザ側の制限）。設置端末をiPadにする場合は、実機で確認してから決める。

音声入力が使えないブラウザでは、自動でキーボード入力欄が出る。
判定も回答も音声のときと同じなので、案内は止まらない。

設置端末はChromeのキオスクモードを想定している。

```
chrome.exe --kiosk --app=https://example.com/webapp/
```

## FAQデータの更新

Flutter版と同じ。`js/config.js` の `REMOTE_URL` に配信URLを設定すると、
起動のたびに裏で最新版を取りに行く。

1. 起動時、ローカルを即座に読む（ブラウザ内の保存 → 無ければ同梱データ）
2. 画面が使える状態になった後、裏で配信URLを取得
3. 取得できて版が新しければ差し替え、ブラウザ内に保存
4. 通信が失敗しても、前回のデータで動き続ける

画面右上に「データ 最新 / 保存済み / 初期データ」と版が表示される。

## 読み上げの声

回答の読み上げは2段構え。

1. **用意した音声ファイル**（`assets/audio/`）があればそれを再生する
2. 無ければブラウザの合成音声で読む

### どこで決めるか

| | 決める場所 | 効く範囲 |
|---|------------|----------|
| 鳴らす音声セット | 管理者画面「読み上げの声」 | 全部の端末 |
| 優先する声・速さ・高さ | 管理者画面「読み上げの声」 | 全部の端末 |
| その端末で使う声 | 案内端末（`?setup=1`） | その端末だけ |

**端末に入っている声は端末ごとに違う**ため、一覧を出して試し聞きできるのは
案内端末の画面だけ。管理者画面では「どれを優先するか」までを決める。

端末で選んだ声は、管理者画面の設定より優先される（その端末の事情が最優先）。

### ブラウザの声を選ぶ

ブラウザによって入っている声が違うため、`js/config.js` の
`PREFERRED_VOICES` に優先順位を書いてある。上から順に探し、
最初に見つかった声を使う。

```js
ja: ['Google 日本語', 'Microsoft Nanami', 'Microsoft Ayumi', 'Kyoko', 'O-ren'],
```

先頭の「Google 日本語」は、Androidアプリ版で使っていた声と同じもの。
Chrome（PC・Android）ならこれが使われる。
PCのChromeではこの声はネット経由のため、**通信が切れると別の声に変わる**。

キャラクターは若い女性なので、どの言語も女性の声を先に並べている。
優先順位の声がどれも入っていない端末では、その言語の声から自動で選ぶが、
このとき男性の声を引かないよう `AVOID_VOICES`（名前の一覧）で避けている。
Web Speech API は声の性別を教えてくれないため、名前で判断するしかない。

`config.js` の `PREFERRED_VOICES` / `VOICE_RATE` / `VOICE_PITCH` は、
**「読み上げ」シートが無いときの既定**として残してある。
シートがあればそちらが使われる。

> 例: 英語の声が Zira（女性）と David（男性）の2つある端末では、
> 以前は David が選ばれていた。

速さと高さは `VOICE_RATE` / `VOICE_PITCH` で変えられる。
キャラクターに合わせて高めにするなら `VOICE_PITCH` を 1.1〜1.2 に。

端末ごとに声を変えたいときは、**職員用の画面**（画面右上のデータ表示を長押し）の
「読み上げの声」から選べる。**対応言語すべてが並び**、声が入っていない言語も
その場で分かる。言語ごとに「試しに読む」で確認できる（その言語の文を読む）。
選んだ声はその端末に記憶される。

### 声が入っていない言語がある場合

読み上げに使える声は、**その端末（OS）とブラウザが持っているものだけ**。
アプリ側では増やせない。

| 端末 | 増やし方 |
|------|----------|
| Windows | 設定 → 時刻と言語 → 言語と地域 → 言語を追加 →「音声認識」「テキスト読み上げ」を含めて入れる |
| iPad・iPhone | 設定 → アクセシビリティ → 読み上げコンテンツ → 声 → 言語を追加 |
| Android | 設定 → システム → 言語と入力 → テキスト読み上げ（音声データを追加） |

Chrome・Edge は、OSの声に加えて自前の声（`Google 日本語` など）も持っている。
これは**ネット経由**のため、通信が切れると使えなくなる。
設置端末をキオスクにする場合は、**OS側に声を入れておく**方が確実。

声が無い言語では、読み上げだけができない。**字幕は出るので案内は止まらない。**

### 用意した音声を使う

決まった声で読ませたい回答は、音声ファイルを作って `assets/audio/` に置き、
Excelの「音声ファイル名」列にファイル名を書く。

VOICEVOXでまとめて作るツールがある。

```
python tools/make_voice.py --list            # 話者の一覧
python tools/make_voice.py --speaker 3       # 全件作る
```

## 3通りの端末で1組のファイルを使う

バスターミナル・であいの館の**据え置き端末**と、**観光客のスマートフォン**で
使い方が違うが、置くファイルは1組でよい。開くURLだけで切り替わる。

| 開くURL | 役割 |
|---------|------|
| `webapp/?place=バスターミナル` | バスターミナルの据え置き端末 |
| `webapp/?place=であいの館` | であいの館の据え置き端末 |
| `webapp/` | 観光客が自分のスマートフォンで開く |

別々のファイルに分けると、片方だけ更新し忘れる。1組にしておけば更新も1回で済む。

違うのは主に次の3点。

| | 据え置き | 観光客のスマートフォン |
|---|---|---|
| 詳しい案内 | **QRコード**（読み取って持ち帰る） | **リンク**（押して開く） |
| 現在地 | URLで固定（位置情報を使わない） | 位置情報で判定 |
| 現在地の変更 | 出さない（勝手に変えられると困る） | 上のバーから選べる |

据え置きの画面にリンクを出しても持ち帰れず、手元の端末にQRコードを出しても
自分の画面は読み取れない。

据え置き端末では位置情報の許可を求めないので、キオスクでそのまま使える。

```
chrome.exe --kiosk --app=https://example.com/webapp/?place=バスターミナル
```

役割は端末に記憶されるので、何かの拍子にURLを見失っても変わらない。

### 見え方の調整（?tune=1）

キャラクターの大きさや吹き出しの位置を、**画面を見ながら**合わせる。

```
https://example.com/webapp/?tune=1
```

立ち絵を直接つまんで動かせる。

- 立ち絵そのもの（点線の枠）… 上下に動かす → 高さ位置
- 左上の白い四角 … 斜めに引く → 大きさ
- 赤い丸 … 口の位置（吹き出しの尻尾が向く先）
- 赤い縦の点線 … 吹き出しが来てよい右端

左下のつまみでも同じ値を動かせる。どちらで動かしても連動する。
決まった数値を管理画面の「キャラクター」へ書き写す。

保存はしない。閉じれば元に戻る。
案内アプリから質問回答集へ書き込む道は用意していない
（観光客の端末から設定が書き換わると困るため）。

### 職員用の設定画面

読み上げの声など、その端末でしか決められない設定は
**URLに `?setup=1` を足したとき**だけ開く。

```
https://example.com/webapp/?place=バスターミナル&setup=1
```

画面の長押しのような隠し操作にすると観光客に偶然見つかるため、
URLを知っている人だけが開ける形にしてある。端末にブックマークしておく。

質問の記録はこの画面からも見られない（管理者画面で見る）。

## 設置場所ごとの案内

ロッカーやATMのように、案内所ごとに答えが違う質問がある。
画面右上の一覧で現在地を選べるほか、位置情報でも判定する。

```js
export const PLACE = 'auto';   // 'バスターミナル' のように固定もできる
```

据え置きの案内端末では場所名を直接書くのが確実（位置情報の許可が不要になる）。
どちらの案内所からも離れている場合は、場所に依存しない「共通」の回答を出す。
位置情報は判定だけに使い、送信も保存もしない。

## AIに答えさせる（任意）

質問回答集で答えられなかったときだけ、AIが案内資料をもとに答える仕組みを
足せる。APIキーをブラウザに置けないため、中継サーバが必要になる。

設定は `js/config.js` の1行だけ。

```js
export const AI_ENDPOINT = '../api/ask.php';   // 空ならAIは使わない
```

置き方と注意点は [server/README.md](../server/README.md) を参照。
AIが答えた回答には、画面に必ず「AIが作成しています」と断りが出る。

中継サーバへは、質問・言語・**いまいる案内所**を送る。
中継サーバ側は質問に近い回答10件だけをAIに渡すので、
ATMやロッカーのように案内所ごとに答えが違うものも、正しい方が選ばれる。

## 利用前の同意

質問した内容を記録して外部へ送るため、使い始める前にその旨を画面で伝える。
文面は `js/consent-text.js`（6言語ぶん）。**提供者の表示もここで直す。**

| 端末 | 出し方 |
|------|--------|
| 観光客のスマートフォン | 初回だけ。一度答えればその端末で覚える |
| 据え置き端末 | 3分間だれも触らなければまた出す（`CONSENT_IDLE_MS`） |

据え置きは次々と別の方が使うので、一度の同意で済ませるわけにいかない。
無操作で戻すときに前の方の質問と回答も消すので、**他人の質問が画面に残らない**。

### 「記録せずに使う」がある理由

同意しないと使えない作りにすると、断った方は案内そのものを受けられなくなる。
観光案内は本来だれでも受けられるべきもので、記録はこちら側の都合である。
断っても**案内はすべて使え、記録だけが止まる**ようにしてある。

断った場合も、その端末の中の記録は残る。これは「よくある質問」の並び順
（その端末でよく聞かれた順）に使うためで、外へは送らない。

### 文面を直すとき

**書いてあることと、実際に送っているものを必ず一致させること。**
実装を変えたら `js/consent-text.js` の冒頭のメモも合わせて直す。

いま伝えている内容:

- 記録する … 質問の内容（文字）／答えられたか／言語／日時／どの案内所か
- 記録しない … 声そのもの・氏名や連絡先・現在地の座標
- ただし … 聞き取りのため、声はブラウザの音声認識サービス（Chromeの場合はGoogle）
  へ送られる。質問集で答えられない質問は、文字にした内容を外部のAIへ送る

音声認識とAIの2つは、こちらの都合ではなく**ブラウザと外部サービスの仕組み**なので、
記録しない側に書くと誤解になる。分けて伝えている。

## 質問ログ

記録する内容はFlutter版と同じ（音声そのものは保存しない）。

**案内端末からは記録を見られない。** 職員用の画面に「質問の記録」を置いていたが、
観光客が触る端末に閲覧口があると、隠した導線でもいずれ見つかる。
記録は中継サーバへ送り、**管理者画面（`admin/`）でだけ**見るようにした。

```
案内端末 ──記録を送る──▶ 中継サーバ ──読み出す──▶ 管理者画面
          (api/log.php)     (JSONL)      (api/logs.php)
```

- 記録は端末内に溜め、5分おきにまとめて送る（閉じる直前にも送る）
- **通信が切れていても案内は止まらない**。送れなかった分は溜めておき、次に送る
- 端末内にも残るが、これは「よくある質問」の並び順（その端末でよく聞かれた順）
  に使うためで、画面からは見られない

送り先は `js/config.js` の `LOG_ENDPOINT`。空にすると送らない。

置き方は [server/README.md](../server/README.md)、
見方は [admin/README.md](../admin/README.md) を参照。

## Flutter版との違い

- 音声認識は端末のエンジンではなくブラウザのもの（Chrome系はGoogleのサーバを使うため、通信が必要）
- 保存先がファイルではなくブラウザ内（localStorage）
- どの言語の音声認識に対応しているかをブラウザが教えてくれないため、
  言語ごとの事前チェックはせず、失敗したときに画面へ出す
