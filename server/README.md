# AI回答の中継（レンタルサーバに置く）

質問回答集で答えられなかった質問に、AIが案内資料をもとに答えるための中継。
ロリポップなど、**PHPが使えるレンタルサーバ**に置く。

## なぜ中継が要るのか

案内アプリはブラウザで動くだけのものなので、そこにAPIキーを書くと
**ページを開いた誰でもキーを読めてしまう**。公開すれば第三者に使われ、
料金が膨らむ。キーはこの中継サーバの中だけに置き、ブラウザには渡さない。

```
ブラウザ（案内アプリ）
   ↓ 質問だけを送る
中継（api/ask.php）  ← APIキーはここだけが持つ
   ↓ 質問 ＋ 案内資料（faq.json）
AI（Gemini など）
```

## ファイル

| ファイル | 役割 |
|----------|------|
| `api/ask.php` | 中継の本体。資料を添えてAIに聞き、答えだけを返す |
| `api/log.php` | 案内端末から質問の記録を受け取り、書き溜める |
| `api/logs.php` | 溜めた記録を管理者画面へ渡す（合言葉が要る） |
| `api/config.sample.php` | 設定のひな形。`config.php` にコピーして使う |
| `api/ping.php` | 設置の確認用（確認が済んだら削除する） |
| `api/.htaccess` | 設定ファイルを外から開けないようにする |
| `api/data/` | 使用回数とAIの回答の記録（書き込み権限が必要） |

## 置き方（ロリポップの例）

### 1. APIキーを用意する

Google AI Studio（<https://aistudio.google.com/>）でAPIキーを作る。
無料枠で試せるが、**無料枠は送った内容が製品の改善に使われる**。
本番運用では有料枠に切り替えること。

### 2. ファイルを置く

公開フォルダが次のようになるようにアップロードする。

```
（公開フォルダ）
├── webapp/          案内アプリ
├── assets/          faq.json・写真・音声・キャラクター画像
└── api/             この中継
    ├── ask.php
    ├── config.php   ← 自分で作る
    ├── .htaccess
    └── data/        ← 書き込み権限を与える（パーミッション 707 など）
```

### 3. 設定を作る

`config.sample.php` を `config.php` という名前でコピーし、中身を埋める。

- `api_key` … AI Studioで作ったキー
- `model` … `gemini-3.8-flash`（軽くするなら `gemini-3.5-flash-lite`）
- `allow_origins` … 案内アプリを置いたURL（例: `https://example.com`）
  **空のままにしないこと。** 誰でも中継を叩けてしまい、料金を他人に使われる
- `max_per_minute` / `max_per_day` … 使いすぎの上限

### 4. 動くか確かめる

ブラウザで `https://（あなたのドメイン）/api/ping.php` を開く。

```
1. PHP: 動いています（8.2.x）
2. 外部への通信: できます
3. AIへの接続: できます（gemini-3.8-flash）
4. 記録の保存先: 書き込めます
```

ここで「2. 外部への通信」が×なら、そのサーバからは外部APIを呼べない。
別の場所（Cloudflare Workers・Cloud Run など）に中継を置く必要がある。

**確認できたら ping.php は必ず削除する。**

### 5. 案内アプリから使えるようにする

`webapp/js/config.js` を開き、中継の場所を入れる。

```js
export const AI_ENDPOINT = '../api/ask.php';
```

空のままなら、これまでどおり「答えられなければ職員へ」だけで動く。
AIを止めたいときも、ここを空に戻せばよい。

## 手元で試す（公開前の確認）

PHPが入っていれば、リポジトリ直下で1つサーバを立てるだけで全部つながる。

```
php -S 127.0.0.1:8000 -t .
```

- 案内アプリ　　… <http://127.0.0.1:8000/webapp/>
- 設置の確認　　… <http://127.0.0.1:8000/server/api/ping.php>

このとき `config.php` は次のようにする（リポジトリの構成に合わせる）。

```php
'faq_path' => __DIR__ . '/../../assets/faq.json',
'allow_origins' => ['http://localhost:8000', 'http://127.0.0.1:8000'],
```

`webapp/js/config.js` の `AI_ENDPOINT` は `'../server/api/ask.php'`。
公開するときは `'../api/ask.php'` に変える。

### WindowsのPHPで「外部への通信ができません」と出る場合

Windows版のPHPには証明書が同梱されていないため、HTTPS通信に失敗する。
<https://curl.se/ca/cacert.pem> を保存し、php.ini に次を書く。

```ini
curl.cainfo = "C:/path/to/cacert.pem"
openssl.cafile = "C:/path/to/cacert.pem"
```

レンタルサーバ側では最初から入っているため、この作業は不要。

## 動き方

1. 観光客が質問する
2. まず質問回答集で探す（ここで9割以上が当たる）
3. 見つからなければ中継へ送り、AIが資料をもとに答える
4. AIも答えられない・8秒で返らない・通信が切れた → 職員へ案内

### 渡す資料は20件だけ

回答は全部で70件以上あるが、AIには**質問に近い20件だけ**を渡している
（`ask.php` の `CONTEXT_LIMIT`）。全件渡すと、

- 料金が5倍以上かかる（送った文の長さで課金されるため）
- 1分あたりの上限に当たり、続けて質問できなくなる
- 関係のない回答が混ざって、答えがぶれる

近さの測り方:

- 日本語・中国語・韓国語は**2文字ずつに刻んで**重なりを数える（語の区切りが無いため）
- 英語・スペイン語・フランス語は**語のまま**数える。英字を2文字に刻むと、
  どの文にも出る並び（th、in、er）ばかり当たって、関係のない回答が選ばれる
- **珍しい語ほど重く数える。**「です」「ここ」のようにどの回答にも出る語で点を付けると、
  文章の長い回答ばかりが上位に来て、本当に関係のある回答が押し出される
- 質問例に出てくる語は、回答文に出てくる語より重く見る
- 「言い換え」シートを使って、観光客の言い方を資料の語へ橋渡しする（銀行→ATM など）

近いものが1件も無ければ、**AIに聞かずに職員へ回す**（料金がかからない）。

### 参考資料

質問回答集は「この質問にはこう答える」という形なので、そこに無い聞かれ方には
答えられない（「雨の日は大丈夫ですか」「冬の靴は」など）。

Excelの**「参考資料」シート**に書いた説明文は、AIが答えを組み立てる下地として
毎回そのまま渡される（件数が少なく短いため、絞らない）。

| | FAQシート | 参考資料シート |
|---|---|---|
| 性格 | 職員が確かめた決まった答え | 背景の説明 |
| 使われ方 | そのまま読み上げる | AIが質問に合わせて言い換える |
| 検索 | キーワードで当てる | 常に渡す |

決まった答えを返したい質問はFAQシートに、
「聞かれ方が読めないが、知っておいてほしいこと」は参考資料シートに書く。

いまいる案内所も一緒に受け取り、**その案内所向けの回答と「共通」だけ**を渡す。
別の案内所の回答を混ぜると、ロッカーやATMの場所を取り違えて案内してしまう。

AIが答えた場合は、画面に**「この回答は案内資料をもとにAIが作成しています」**と
必ず表示される。職員の回答と見分けがつくようにするため。

## AIに与えている制限

`ask.php` の中で、次のように指示している。

- 資料に書かれていないことは答えない（推測も一般知識も使わない）
- 時刻・料金・可否は、資料に明記がある場合のみ
- 危険に関わる質問（けが・急病・事故・熊・川）は答えず職員へ
- 答えられないときは答えない。**答えないことは失敗ではない**

無回答より誤答のほうが害が大きい。観光客が「答えをもらえた」と思って
職員に聞く機会を失うため、迷ったら答えさせない方針にしている。

## 記録の見方

`api/data/ai_log.jsonl` に、AIが何を聞かれて何と答えたかが1行1件で残る。
FTPで取り出して確認し、**良い回答は質問回答集（Excel）に登録する**。
登録すれば次から即座に答えられるようになり、AIに頼る割合が減っていく。

```json
{"at":"2026-09-24T14:12:00+09:00","lang":"ja","place":"バスターミナル",
 "question":"半日あれば足りますか","model":"openai/gpt-oss-120b",
 "candidates":["shuyu_time","bus_next",...],"prompt_chars":1727,
 "result":"answered","answer":"……","sources":["shuyu_time"]}
```

| 項目 | 見かた |
|------|--------|
| `candidates` | AIに渡した資料。的外れなものばかりなら、「言い換え」シートの見直しどき |
| `prompt_chars` | 送った文の長さ。料金と上限の当たり具合の目安 |
| `result` | `answered` / `not_found`（AIが答えなかった） / `no_candidate`（資料に近いものが無く、AIに聞かなかった） / `error` |

## 質問の記録

案内端末は、聞かれた質問と答えられたかどうかを `api/log.php` へ送る。
`data/question_log.jsonl` に1行1件で溜まり、**管理者画面から見る**。

案内端末の側には記録を見る画面を置いていない。
観光客が触る端末に閲覧口があると、隠してあってもいずれ見つかるため。

```
案内端末 ──POST──▶ api/log.php ──▶ data/question_log.jsonl
管理者画面 ──GET───▶ api/logs.php ──▶ 同じファイルを渡す
```

記録される内容（音声そのものは送らない）。

```json
{"at":"2026-09-30T10:00:00+09:00","client":"バスターミナル",
 "place":"バスターミナル","lang":"ja","recognized":"トイレはどこですか",
 "faq_id":"toilet","source":"faq","category":"facility","voice":"recorded",
 "received":"2026-09-30T10:00:03+09:00"}
```

- `client` … どの端末か（`バスターミナル` / `であいの館` / `観光客`）。統計を分けるのに使う
- `source` … `faq`（質問回答集） / `ai`（AIが作成） / `none`（答えられず職員へ）

### 合言葉を決める

記録は観光客の声そのものなので、`config.php` に決めた合言葉を持つ人だけが読める。

```php
'log_token' => 'ここに長い無作為の文字列',
```

作り方の例:

```
php -r "echo bin2hex(random_bytes(24));"
```

**空のままだと誰も読めない。** 空を「制限なし」にすると、
設定し忘れがそのまま公開になるため、あえてそうしてある。
同じ文字列を管理者画面の Secrets にも書く。

書き込み（`api/log.php`）の方は、`allow_origins` で案内アプリと同じサイトからだけ
受け付ける。誰でも書き込める状態だと、記録が荒らされて統計が使えなくなる。

## 同じ資料を毎回送るので、使い回しを効かせている

指示文と参考資料（約6,000文字）は、どの質問でもまったく同じ。
これを「使い回す」指定（プロンプトキャッシュ）を付けているので、
2回目以降はその分の料金が**10分の1**になる。

そのために、送る中身を2つに分けている。

| | 中身 | 変わるか |
|---|------|----------|
| `system` | 指示文＋参考資料（約6,000文字） | **毎回同じ** → 使い回す |
| `messages` | 選んだ資料＋答える言語＋質問（約3,000文字） | 質問ごとに変わる |

答える言語を `messages` 側に置いているのは、言語ごとに別物にしないため。
6言語すべてで同じ使い回しが効く。

効くのは**直前の質問から5分以内**。閑散期は効かないが、
効かなかったときに少し高くなるだけで、損にはならない。

効いているかは記録で分かる。

```json
"usage": {"in": 120, "out": 30, "cache_write": 4400, "cache_read": 0}
```

`cache_read` が増えていれば効いている。いつも0なら、
資料か指示文が毎回変わっていないかを疑う。

切るときは `config.php` の `'cache' => false`。

## 資料は配信URLからも読める

管理画面から反映すると、新しい質問回答集はGitHubに置かれる。
案内アプリはそこから直接読むが、中継サーバが自分の中の古いファイルを見ていると、
**画面とAIで答えが食い違う。**

`config.php` の `faq_url` に、案内アプリの `REMOTE_URL` と同じURLを入れておくと、
中継サーバもそちらを読む。

```php
'faq_url' => 'https://raw.githubusercontent.com/ユーザ名/リポジトリ名/main/assets/faq.json',
'faq_cache_path' => __DIR__ . '/data/faq_cache.json',
'faq_cache_minutes' => 30,
```

毎回取りに行くと観光客を待たせるので、控えが30分より新しいうちはそれを使う。
取りに行けなかったときは、控え → 同梱のファイル の順に落ちる。
**資料が読めないことより、案内が止まることの方が困る**ため。

## 注意

- **掲示が必要**。質問内容を記録し、外部のAIサービスへ送るため、
  設置時にその旨の掲示を行うこと
- 1問あたりの料金はおよそ**1円**（Claude Haiku 4.5、使い回しが効けば0.6円ほど）。
  1日100件でも月2,000〜3,000円。賢さが要るなら `claude-sonnet-5-5` に上げられるが、
  料金は2倍になる
- `config.php` の `max_per_minute` / `max_per_day` が使いすぎの歯止め。
  クレジットを使い切ると答えられなくなるので、上限は必ず設定しておく
- モデル名は変わる。`config.php` の `model` を直せば切り替えられる
