# 白川郷 音声案内チャットボット（Webアプリ）

「押して話す → 音声認識 → FAQ検索 → 回答表示＆音声再生」の流れをブラウザ内で完結させる。
各処理は差し替え可能な部品として分離してある。

仕様変更により、本体をAndroidアプリ（Flutter）から**Webアプリ**に切り替えた。
画面の配置・色・動きはAndroid版をそのまま再現し、FAQの判定も同一にしてある。
インストールが要らないため、タブレット・PC・スマートフォンのどれでも同じURLで使える。

| | 場所 | 用途 |
|---|------|------|
| **Webアプリ（本体）** | `webapp/` | 設置・公開するのはこれ（[webapp/README.md](webapp/README.md)） |
| デモ（Streamlit） | `demo/` | 外部の方に内容だけ確認していただく用 |
| 管理画面 | `admin/` | 職員がブラウザで質問回答集を編集する用（[admin/README.md](admin/README.md)） |
| AI回答の中継 | `server/` | 質問回答集で答えられない質問にAIが答えるための中継（任意・[server/README.md](server/README.md)） |
| Androidアプリ（旧） | `lib/`, `android/` | 切り替え前の実装。参照用に残してある |

## FAQデータの更新の流れ

```
管理画面（admin/）  ←  職員がブラウザで追加・修正
        ↓  日本語を入れると他の5言語へ自動翻訳
tools/faq_master.xlsx（質問回答集・正データ）
        ↓  tools/build_faq.py（検証つき変換。管理画面からも実行できる）
     faq.json
        ↓  GitHub等にアップロード
   配信URL
        ↓  起動時に自動取得
   タブレット
```

Excelを直接編集してもよい。管理画面とExcelは同じファイルを見ている。
ただし同じ項目を同時に直すと、あとから保存したほうが残る。

コマンドで変換する場合:

```
python tools/build_faq.py --source tools/faq_master.xlsx --out assets/faq.json --assets assets
```

「掲載開始日」「掲載終了日」を入れた項目は、期間外のときは書き出されない
（お祭りなど期間限定の案内を、消し忘れずに出し入れするための仕組み）。

## 読み上げの声

2段構え。用意した音声ファイルがあればそれを再生し、無ければブラウザの合成音声で読む。

ブラウザの声は `webapp/js/config.js` の `PREFERRED_VOICES` で優先順位を決めている。
先頭の「Google 日本語」はAndroidアプリ版と同じ声で、Chromeならこれが使われる。
端末ごとの変更は職員用の画面（データ表示を長押し）からできる。

キャラクターに合った声にするなら、VOICEVOXで音声を作って置く。

```
python tools/make_voice.py --list         # 話者の一覧を見る
python tools/make_voice.py --speaker 3    # その話者で全件作る
```

作った音声は `assets/audio/` に入り、Excelの「音声ファイル名」列に記録される。
**設置・公開で使う場合は、話者ごとの利用規約に従いクレジット表記が必要。**

## 設置場所ごとの案内

ロッカーやATMのように、**案内所によって答えが違う**質問がある。
（バスターミナルには「コインロッカーがございます」、
　であいの館には「この駐車場や近隣にはございません」）

そのため、FAQシートの「設置場所」列で回答を出し分ける。

| 設置場所 | 使われ方 |
|----------|----------|
| 共通 | どこにいても使う。場所に依存しない言い方で書く |
| バスターミナル | その案内所の近くにいるときだけ使う |
| であいの館 | 同上 |

### どの案内所にいるかの決め方

案内アプリは次の順に判断する。

1. 画面右上で職員が選んだ場所（その端末に覚える）
2. `webapp/js/config.js` の `PLACE`（据え置き端末はここに書く）
3. 位置情報から、範囲内でいちばん近い案内所
4. どれも分からなければ「共通」の回答だけで案内する

座標と範囲は、Excelの**「設置場所」シート**に書く。
座標はGoogleマップで右クリック→座標をコピーで調べられる。

据え置きの案内端末では、位置情報を使わず `PLACE` に場所名を書くのが確実。

```js
export const PLACE = 'バスターミナル';   // 'auto' なら位置情報で判定
```

### 回答の探し方

1. いまいる案内所向けの回答を探す
2. 見つからなければ「共通」の回答を探す
3. それも無ければ職員へ案内する

このため、**場所ごとの回答と共通の回答は、同じ質問例で構わない**。
近くにいる人にはその案内所の答えが、離れている人には共通の答えが出る。

## 案内画面のキャラクター

画面に立つキャラクターは、Excelの**「キャラクター」シート**で決める。
画像は `assets/character/` に置く。

| 列 | 意味 |
|----|------|
| 名前 | 画面に出す呼び名 |
| ID | 内部で使う名前（英数字）。利用者の選択を覚えるのに使う |
| 通常 | 待機中の画像のファイル名 |
| 聞き取り中 / 話している | **空欄でよい。** 空なら「通常」の画像を使う |
| 口の高さ / 顔の広さ | 吹き出しの尻尾を口元へ向けるための値（高さに対する割合） |
| 大きさ | 1.0が基準。横長のキャラクターは小さめにする（0.3〜0.5） |
| 高さ位置 | 0＝下端に立たせる（人物）／1＝上端まで持ち上げる（ゆるキャラは0.75） |
| 既定 | TRUE を入れた1件が、端末を開いたときのキャラクター |
| 有効 | FALSE にすると一覧に出ない |

**表情差分が無くても動く。** 1枚だけのキャラクターは、
聞き取り中も話している間も同じ絵のまま案内できる。

縦横比は画像から自動で読む（書き間違いが起きないように）。
縦長の人物と横長のゆるキャラでは吹き出しの位置が変わるため、
キャラクターを選び直すたびに画面の配置も合わせて変わる。

**職員は管理画面の左側で既定を決める。利用者は案内画面の上のボタンで選び直せる**
（選んだものはその端末に残る）。

```
python tools/add_characters.py     # シートを作る（初回のみ）
```

URLで指定もできる（据え置きを2台置いて、別々のキャラクターにする場合）。

```
webapp/?place=バスターミナル&character=yuru
```

### 大きさと吹き出しの位置

横長のキャラクターを高さいっぱいに立たせると、**幅＝高さ×縦横比**が
画面を覆ってしまう。ふだんの大きさは「大きさ」列で決め、
そのうえで幅にも歯止め（画面の7割弱）を入れてある。

縦長の立ち絵は端を少しはみ出させて大きく見せるが、
ゆるキャラのように絵として完結しているものは切らない（縦横比で自動判定）。

**吹き出しは口元の高さに合わせて上下する。** 口が下の方にあるキャラクターでは、
吹き出しごと下へずらして、尻尾がちょうど口元に来るようにしている
（ずらさずに吹き出しを伸ばすと、中身が2行でも縦長の空き箱になる）。

**ゆるキャラは「高さ位置」で持ち上げる。** 地面に立つものではないので、
下端に置くと顔が低くなり、吹き出しも一緒に下がってしまう。
0.75 まで持ち上げると、人物のキャラクターと同じ高さに吹き出しが並ぶ。

見え方は数字で確かめられる。

```
python tools/measure_characters.py          # 大きさを測る
python tools/measure_characters.py --shot   # 画面の写真も撮る
```

## 設定はどこで直すか

Excelと管理画面のどちらでも直せる。**同じファイルを見ているので結果は同じ。**

| シート | 管理画面での場所 |
|--------|------------------|
| FAQ / 多言語 | 「質問を追加・修正する」「まとめて翻訳する」 |
| 言い換え / 設置場所 / 参考資料 / キャラクター | 「その他の設定」 |
| 音声セット / 読み上げ | 「読み上げの声」 |

管理画面は列を**見出しの名前**で探す。列を足しても壊れない
（列番号で探していたときは、列を1つ足しただけで別の列を読んでしまった）。

### 音声ファイルはmp3にする

VOICEVOXが書き出すWAVは1件0.5MBほどで、73件で37MBになる。
観光客のスマートフォンは回答のたびにこれを読み込むので、mp3に変換しておく。

```
python tools/convert_audio.py --dry-run   どうなるかだけ見る
python tools/convert_audio.py             変換してExcelも書き換える
```

64kbps・モノラル・24kHzで書き出す。案内の読み上げなので、聞いた感じは変わらない。
変換すると「音声ファイル名」列の拡張子も一緒に書き換わる。

> 実測: 75.1MB → 12.6MB（17%）。1回答あたり約527KB → 約86KB。

## 読み上げの声の設定

Excelの**「読み上げ」シート**で、言語ごとに決める。

| 列 | 意味 |
|----|------|
| 言語 | ja / en など |
| 優先する声 | 上から順に探す。カンマ区切り。名前の一部が合えば採用 |
| 速さ | 1.0が標準。小さいほどゆっくり |
| 高さ | 1.0が標準。大きいほど高い声 |

「音声セット」シートの**「既定」**列で、いつも鳴らす音声（VOICEVOXなどで
作ったもの）を決める。どちらも管理者画面の「読み上げの声」から変えられる。

**端末に入っている声は端末ごとに違う。** ここで決められるのは
「どれを優先するか」までで、入っている声の確認と試し聞きは
案内端末の画面（`?setup=1`）で行う。

```
python tools/add_voice_settings.py   # シートを作る（初回のみ）
```

## 参考資料（AIが答えを組み立てる下地）

質問回答集は「この質問にはこう答える」という形なので、そこに無い聞かれ方には
答えられない（「雨の日は大丈夫ですか」「冬の靴は」など）。

Excelの**「参考資料」シート**に書いた説明文は、AIが答えを作るときに毎回渡される。

| 列 | 意味 |
|----|------|
| 見出し | 何についての説明か（例: 冬の服装と靴） |
| 内容 | 説明文。AIが質問に合わせて言い換えて使う |
| 有効 | FALSE にすると使われない |
| 備考 | 確認状況などのメモ |

| | FAQシート | 参考資料シート |
|---|---|---|
| 性格 | 職員が確かめた決まった答え | 背景の説明 |
| 使われ方 | そのまま読み上げる | AIが質問に合わせて言い換える |
| 読み上げ音声 | 用意できる | 用意しない（その場で作られる文のため） |

決まった答えを返したい質問はFAQシートに、
「聞かれ方が読めないが、知っておいてほしいこと」は参考資料シートに書く。

**ここに書いたことは、AIがそのまま根拠にする。** 確かめていないことは書かない。

### 中身は質問回答集から自動で作れる

`tools/fill_reference.py` を実行すると、**場所によらない回答48件を分類ごとにまとめた行**が
「参考資料」シートに入る（見出しが `【質問回答集より】` で始まる行）。

- **回答文は書き換えない。** 要約すると「小学生は半額」のような条件が落ちて、
  そこだけ読んだAIが条件なしで答えてしまう
- **案内所ごとに違う回答は入れない。** ATMやロッカーを毎回全部渡すと、
  離れた案内所の答えを混ぜて案内してしまう。「この話題は案内所で違う」とだけ伝える

`【質問回答集より】` で始まる行は実行のたびに作り直される。
職員が手で足した行はそのまま残る。

## 言い換えへの対応

観光客は、登録した質問例とは違う語で聞いてくる（「銀行ありますか」「鞄を置きたい」）。
Excelの**「言い換え」シート**がその差を吸収する。

| 列 | 意味 |
|----|------|
| 言語 | ja / en など |
| 代表語 | 質問例に実際に書かれている語（例: atm） |
| 同じ意味の語 | 観光客が言いそうな別の言い方（例: 銀行）。1行に1つ |

検索のときだけ使う。入力文に「同じ意味の語」があれば、その「代表語」も
入力文に含まれているものとして照合する。回答文には影響しない。

行を足すときは、**代表語が質問例に実際にある語かどうか**を確かめること。
無い語を代表語にしても、どの質問にも当たらない。

初回の表は次のコマンドで作った（すでに作成済み。作り直す必要はない）。

```
python tools/init_synonyms.py --source tools/faq_master.xlsx
```

### 効果の測り方

観光客が言いそうな言い方を集めた `tools/eval/questions.jsonl` で測る。

```
python tools/eval/run_eval.py                      # 今の状態
python tools/eval/run_eval.py --no-synonyms        # 言い換えを使わない状態
```

測るのは3つ。**正解**・**無回答**（職員へ回った分）・**誤答**（別の回答を返した）。
誤答は無回答より害が大きい。観光客が「答えをもらえた」と思って
職員に聞く機会を失うため、ここは0に保つ。

言い換えを入れた効果（2026年9月時点・130件で測定）:

| | 正解 | 無回答 | 誤答 |
|---|---|---|---|
| 言い換えなし | 75.4% | 23.7% | 0.8% |
| 言い換えあり | **95.8%** | 4.2% | **0%** |

### 端末側の動作（オフライン優先）

1. 起動時、ローカルを即座に読む（保存済み → 無ければ同梱データ）
2. 画面が使える状態になった後、裏で配信URLを取得
3. 取得できて版が新しければ差し替え、キャッシュに保存
4. 通信が失敗しても、前回のデータで動き続ける

配信URLは `webapp/js/config.js` の `REMOTE_URL`（Android版は
`lib/faq_repository.dart` の `remoteUrl`）に設定する。
空のままなら同梱データのみで動作する（オフライン専用運用）。

画面右上に「データ 最新 / 保存済み / 初期データ」と版が表示されるので、
職員が更新の反映を確認できる。

## 動かす

リポジトリ直下で簡易サーバを立て、`/webapp/` を開く。

```
python tools/serve.py
```

→ http://localhost:8000/webapp/

AIの回答まで試すときは、PHPの簡易サーバを使う（中継が動くのはこちら）。

```
php -S 127.0.0.1:8000 -t .
```

> `python -m http.server` は使わないこと。ブラウザが古いファイルを使い続け、
> 直したものが反映されない。

`assets/` と `webapp/` を同じ場所に置いて配信すれば、サーバ側の処理なしで公開できる
（GitHub Pages など）。**マイクは https か localhost でしか使えない**ため、
公開するときは必ず https にする。設置端末はChromeのキオスクモードを想定している。

音声入力に対応していないブラウザ（Firefoxなど）では、自動でキーボード入力欄に
切り替わる。判定も回答も音声のときと同じなので、案内は止まらない。

詳細は [webapp/README.md](webapp/README.md) を参照。

## 段階的な発展計画

- 第1段階（現在）: 端末標準の音声認識 ＋ キーワード一致 ＋ 音声ファイル/端末音声の併用

## 多言語対応

日本語・English・中文・한국어の4言語。画面上部のボタンで手動切り替え。

自動判定にしていないのは、音声認識が「これから何語が話されるか」を事前に
指定する必要があるため。騒音下では自動判定が誤りやすく、観光客が自分で
選ぶ方が確実になる。どの言語が選ばれたかは利用統計としても使える。

翻訳は `tools/faq_master.xlsx` の「多言語」シートに記入する。
未記入の項目は日本語で表示し、画面にその旨を断り書きとして出す
（翻訳が揃うまで案内が止まらないようにするため）。

音声は、その言語の音声ファイルがあれば再生し、無ければブラウザの音声合成が
その言語で読み上げる。その言語の音声認識が使えない場合は、画面に表示される。
- 第2段階: 音声認識を whisper.cpp でオフライン化、FAQ検索を埋め込みベクトル化
- 第3段階: FAQ検索・AI返答をクラウド（Python側）へ、質問ログを蓄積して分析


## 質問ログ

何を聞かれ、答えられたかを端末内に記録する。
頻出質問の把握とFAQ拡充の根拠になり、研究データとしても使う。

### 記録する内容

日時 / 言語 / 認識された質問文 / ヒットしたFAQのID / 分類 /
翻訳を日本語で代替したか / 読み上げの方法

音声そのものは保存しない。

### 確認する

画面右上のデータ表示を**長押し**すると職員用の画面が開く。
観光客の目に触れないよう、通常のUIからは辿れない導線にしてある。

- 回答率（職員に回さず完結できた割合の目安）
- 答えられなかった質問の一覧 ← FAQに追加する候補
- よく聞かれた質問 ← 音声を優先して用意すべきもの
- 言語別の利用

### PCで分析する

職員用画面の「JSONLで保存」から `question_log.jsonl` を取り出し、

```
python tools/analyze_log.py question_log.jsonl
python tools/analyze_log.py question_log.jsonl --csv out.csv
```

時間帯別の利用状況まで集計される。`--csv` を付けるとExcelで開ける形式で出力する。

### 設置時の注意

質問内容を記録するため、**「音声を認識し、質問内容を記録します」の掲示が必要**。
保存期間と匿名化の方針もあわせて決めておく。大学の研究として設置する場合は
倫理審査の対象になる可能性がある。
